# 工具注册规范

## 注册前准备
注册工具前需要明确工具名称、功能描述、负责人、标签、所属一级分组、功能型和唯一的 namespace。namespace 建议使用小写英文短名，例如 `device-query`，并对应文件中心的专属空间。

## 支持的工具类型
- `internal`：平台已有的前端页面路由，例如 `/capabilities/spec`，不能填写后端 API 地址。
- `static`：部署在 `/tools/` 下的静态前端资源，namespace 为 `<slug>` 时地址必须是 `/tools/<slug>/`，并填写入口文件。
- `external`：HTTPS 外部服务地址。
- `streamlit`：预先部署并由反向代理暴露的 Streamlit 应用。站内代理地址必须是与 namespace 一致的 `/<slug>/`，也可填写完整 HTTPS 地址。

服务器可执行程序当前未开放注册或运行。后续如需启用，必须使用独立任务队列、固定镜像、非 root 用户、CPU/内存/超时限制和审计，不能直接执行管理员填写的任意路径。

## 发布检查
发布前应验证入口可访问、描述和标签可检索、负责人明确、文件 namespace 不冲突，并为对应用户或角色配置工具权限。工具停用时应保留审计记录，不应只依赖前端隐藏。

## Agent 能力边界
Agent 可以解释注册流程、生成注册草稿并推荐工具；涉及创建工具、修改权限、启动可执行程序或部署服务的操作必须由有权限的用户确认后执行。
