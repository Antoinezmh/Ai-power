# 统一工具文件空间

## 目标与边界

文件中心统一管理工具可由用户上传、下载、授权和复用的文件资产。工具的数据库、向量索引、模型、缓存、日志和临时文件仍使用各自的运行卷，不纳入文件中心资产表，避免用户误删导致工具损坏。

每个工具最多登记一个共享文件空间：

```text
<FILE_STORAGE_ROOT>/<一级分组>/<功能型>/<namespace>/
```

`namespace` 是唯一逻辑标识。浏览器和外部工具不能提交绝对路径；平台只接受 `tool_id`，再从工具注册信息解析实际目录。

## 生命周期

1. 管理员注册工具，并按需打开“注册到文件中心”。
2. 后端校验分组、功能型和 namespace，创建受控目录。
3. `GET /api/v1/files/spaces` 只返回当前用户有权限访问的已注册空间。
4. 文件中心上传时选择工具，前端同时提交 `tool_id` 和注册坐标；后端复核二者一致后写入。
5. 工具授权自动派生同一空间的 read/write/manage 权限。关闭文件空间后不再作为上传目标，也不再从工具授权派生文件权限。
6. 空间内仍有文件时，平台禁止直接修改工具的分组/namespace或删除工具，防止产生孤儿文件。应先在文件中心迁移文件；仅停止使用时优先停用工具。

## RAG 工具接入

推荐把文件中心空间作为 RAG 的“资料入口”，把索引作为工具私有运行数据：

```yaml
services:
  rag-tool:
    volumes:
      - file_storage:/data/files:ro
      - rag_runtime:/opt/rag
    environment:
      RAG_SOURCE_DIR: /data/files/器件组/原始数据/rag-loader
      RAG_INDEX_DIR: /opt/rag/index
```

RAG 服务监听或定期扫描 `RAG_SOURCE_DIR`，以文件 ID、内容哈希和更新时间维护增量索引。删除或移动源文件时应同步删除旧向量；索引失败只更新工具侧任务状态，不修改文件中心原文件。

如果工具需要向文件中心产出报告，将共享空间挂载为读写；只做加载/检索时使用只读挂载。部署时容器内统一挂载根建议为 `/data/files`，接口返回的 `relative_path` 和 `tool_mount_path` 可用于生成部署配置。

## 接口兼容

- 新上传推荐提交 `tool_id`。
- 旧客户端仍可提交 `group_name + func_type + namespace`，但该三元组必须匹配一个已启用的工具空间。
- 分片上传的 init 与 complete 都会重新解析并校验目标，不能在上传过程中切换目录。
