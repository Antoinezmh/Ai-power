# 第三方工具集成方案（正式版）

> 面向类型：**有源码、可跨平台、自带前端页面的后端业务工具**（如「CP 报表生成器」）。
> 集成方式：**方式乙 —— nginx 统一入口 + 容器化 + 前端自动推导 API 地址**。
> 适用环境：开发（本机）/ 生产（Linux 服务器）。部署后用户用 Windows 浏览器访问 `http://<服务器IP>/<前缀>/`。

---

## 一、方案架构

```
用户 Windows 浏览器
      │  http://<服务器IP>    (nginx 80 统一入口)
      ▼
Linux 服务器 nginx (80)
   ├── /            → 平台前端
   ├── /api/        → 平台后端
   ├── /<前缀>/     → 本工具  (nginx 反代 → 工具容器:内部端口)   ← 本次集成点
```

**要点**

- 每个工具一个 URL 前缀（如 `/cp/`），nginx 按前缀转发到工具容器。
- 工具容器**只 expose 内部端口，不映射宿主机端口** → 规避端口冲突，满足「端口不固定」。
- 工具**前端页面由工具自己的后端托管**（后端根路由返回页面），页面里 **API 地址自动推导**（`window.location.origin + 前缀`），换 IP/端口/域名**无需改前端代码**。

## 三、标准集成三步

### 第 1 步：把工具容器化

在 `third_party/<tool_name>/` 下准备：

```
third_party/<tool_name>/
├── app.py                  # 后端主程序：
│                           #   - 去掉 Windows 专属依赖（如 pythoncom）
│                           #   - 监听 0.0.0.0:内部端口
│                           #   - 增加根路由 '/' 返回 index.html（托管页面）
├── <业务模块>.py           # 业务逻辑（需跨平台）
├── index.html              # 前端页面（API 地址自动推导本工具前缀）
├── requirements.txt        # 跨平台依赖（不含 Windows 专属包）
├── Dockerfile              # 容器构建（含中文字体，若用 matplotlib）
├── .dockerignore           # 排除 dist/venv/__pycache__ 等
└── data/                   # 用户数据目录（挂载卷）
```

**Dockerfile 要点**（参考已有 `cp_report_generator/Dockerfile`）：

- 基础镜像：`python:3.11-slim`
- 安装依赖：`pip install -r requirements.txt`
- 装中文字体（若工具用 matplotlib）：`fonts-wqy-zenhei` + 字体回退配置
- `COPY index.html .`（供后端托管页面）
- `EXPOSE <内部端口>` + `CMD ["python", "<主程序>.py"]`

### 第 2 步：接入 nginx 反代

在 **生产** `nginx.conf.prod` 和 **开发** `nginx.conf.dev` 各加一段 location：

```nginx
location /<前缀>/ {
    proxy_pass http://<容器名>:<内部端口>/;   # 生产：容器名；开发：localhost
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_read_timeout 600s;    # 长耗时分析任务可调大
    proxy_send_timeout 600s;
}
```

同时在 `docker-compose.yml` 增加工具服务：

```yaml
<容器名>:
  build:
    context: ./third_party/<tool_name>
    dockerfile: Dockerfile
  container_name: <容器名>
  expose:
    - "<内部端口>" # 只内网，不映射宿主
  volumes:
    - ./third_party/<tool_name>/data:/data
  restart: unless-stopped
  networks:
    - aix-network
```

并把它加进 `nginx.depends_on`。

### 第 3 步：平台数据库登记工具

在平台 `tools` 表插入/更新该工具记录：

| 字段     | 值                                                    |
| -------- | ----------------------------------------------------- |
| `name`   | 工具显示名（如 CP 报表生成器）                        |
| `type`   | `external`                                            |
| `source` | `/cp/`（URL 前缀，前端 `window.open` 相对路径打开）   |
| `entry`  | 空                                                    |
| `config` | 记录部署信息：容器名、内部端口、数据目录、HTTP 前缀等 |

## 四、前端 API 地址自动推导（工具页面内）

工具前端 `index.html` 里的 `API_BASE` 需这样写，保证换环境不用改：

```js
// 由当前页面 URL 推导工具前缀（如 /cp），API 请求自动带上前缀由 nginx 路由
(function () {
  var p = window.location.pathname; // /cp/ 或 /cp/index.html
  var normalized = p.endsWith("/") ? p : p + "/";
  var seg = "";
  var parts = normalized.split("/");
  for (var i = 0; i < parts.length; i++) {
    if (parts[i]) {
      seg = parts[i];
      break;
    }
  }
  window.API_BASE = window.location.origin + (seg ? "/" + seg : "");
})();
var API_BASE = window.API_BASE;
// 后续请求：fetch(`${API_BASE}/api/xxx`)
```

## 五、运行与访问

### 生产（服务器）

```bash
docker compose up -d --build            # 默认生产（nginx.conf.prod）
# 浏览器访问 http://<服务器IP>/<前缀>/
```

前提：放行 80 端口、数据目录有写权限、中文字体已装。

### 开发（本机，不依赖 docker）

1. 工具后端：`cd third_party/<tool_name> && python app.py`（监听 0.0.0.0:内部端口）
2. 平台后端：venv 跑 fastapi（读开发配置 SQLite）
3. 前端：vite dev（3000），`vite.config.ts` 的 proxy 增加：
   ```js
   '/<前缀>': { target: 'http://localhost:<内部端口>', changeOrigin: true,
                rewrite: p => p.replace(/^\/<前缀>/, '') }
   ```
4. 浏览器访问 `http://localhost:3000/<前缀>/`
